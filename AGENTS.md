# Задание для AI-агента: «Список задач»

## Цель

Создать простой, аккуратный и корректно работающий веб-сайт To-Do List с помощью AI-инструмента (например, ChatGPT, Cursor или Claude Code).

## Обязательный функционал

1. **Добавление задач.** Пользователь вводит текст и добавляет задачу в список.
2. **Отметка выполнения.** Пользователь может отметить задачу выполненной и вернуть её в активное состояние. Выполненные задачи визуально отличаются от активных.
3. **Удаление задач.** Пользователь может удалить отдельную задачу.
4. **Сохранение данных.** Задачи, их порядок и состояние выполнения сохраняются после обновления страницы. Для простого приложения достаточно `localStorage`.

## Интерфейс и удобство использования

- Дизайн свободный, но визуально аккуратный и понятный.
- Интерфейс должен корректно работать на компьютерах и мобильных устройствах.
- Предусмотреть поле ввода, кнопку добавления, список задач, элементы отметки выполнения и удаления.
- Не добавлять пустые задачи или задачи, состоящие только из пробелов; обрезать пробелы по краям текста.
- Поддержать добавление задачи по Enter.
- Использовать доступные элементы управления: подписи для полей и кнопок, управление с клавиатуры и видимый фокус.
- Отображать понятное состояние пустого списка.
- Выводить введённый текст безопасно, без интерпретации как HTML.

## Технический подход

- Стек выбрать самостоятельно с учётом существующего проекта. Для этой задачи достаточно HTML, CSS и JavaScript; фреймворк не обязателен.
- Не усложнять решение: сервер, регистрация и база данных не требуются.
- Хранить для каждой задачи уникальный идентификатор, текст и признак выполнения.
- Обновлять сохранённые данные после добавления, изменения состояния и удаления.
- Обрабатывать некорректные сохранённые данные и недоступность `localStorage` без падения интерфейса. При невозможности сохранения сообщать пользователю, что изменения не сохранятся после обновления.
- Сохранять код понятным, с минимальным количеством зависимостей.

## Проверка готовности

- [ ] Новая непустая задача появляется в списке.
- [ ] Пустой ввод и ввод из пробелов не создают задачу.
- [ ] Задачу можно отметить выполненной и снова сделать активной.
- [ ] Можно удалить нужную задачу, не затрагивая остальные.
- [ ] После обновления страницы сохраняются задачи и их состояния.
- [ ] После обновления удалённая задача не появляется снова.
- [ ] Повторяющиеся тексты задач не мешают независимо изменять и удалять задачи.
- [ ] Длинные тексты не ломают вёрстку.
- [ ] Интерфейс удобен на узком экране и доступен с клавиатуры.
- [ ] В штатном сценарии нет ошибок в консоли браузера.

## Результат и передача

1. Подготовить код проекта для публикации в GitHub.
2. Добавить `README.md` с описанием проекта, функциональности, инструкциями запуска и проверки.
3. Кратко и достоверно указать, какие AI-инструменты использовались и для каких задач. Не заявлять об использовании инструментов, которые фактически не применялись.
4. Передать ссылку на GitHub-репозиторий с кодом проекта.
5. По возможности опубликовать рабочий сайт (например, на GitHub Pages, Vercel или Netlify) и передать ссылку. Это преимущество, а не обязательное требование.
6. Не выдумывать ссылки, результаты тестов или факт публикации. Если публикация требует доступа к аккаунту, явно указать оставшиеся действия.
